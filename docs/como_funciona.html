01¿Qué problema resuelve?

Para una persona en silla de ruedas, con movilidad reducida, con un cochecito o con valijas, que un ascensor o una escalera mecánica del subte funcione o no cambia por completo el viaje.

EMOVA, la empresa que opera el subte de Buenos Aires, publica en internet el estado de esos equipos en ese momento, pero:

  • no guarda memoria: no se puede saber cuántas veces se rompió un ascensor el mes pasado ni cuánto tiempo estuvo fuera de servicio;
  • no es fácil de mirar: son datos pensados para computadoras, no para personas.

Este proyecto consulta esa información cada 2 minutos, la guarda y arma un historial, y la muestra en una página web con listados, gráficos y un mapa.

03Los servicios, uno por uno

🚇 EMOVA, la fuente

EMOVA tiene una dirección web pública que responde con la lista completa de líneas → estaciones → equipos y dice, para cada uno, si funciona o no. Hoy son unos 424 equipos en las líneas A, B, C, D, E y H. No hace falta usuario ni contraseña: es información pública.

🤖 El robot con despertador, dentro de Supabase

El robot vive en el mismo servicio donde se guardan los datos, Supabase, y tiene dos partes: un despertador, una tarea programada que suena cada 2 minutos, y una función, un pequeño programa que en ese momento le pregunta a EMOVA cómo están los equipos y anota lo que cambió. Como todo pasa dentro de Supabase, no hace falta ninguna otra computadora ni servicio.

Además, la página web también “despierta” a la función cada vez que alguien entra, para mostrar datos lo más frescos posible.

🗄️ Supabase, la libreta

Un servicio de base de datos en la nube, donde además corre el robot. Su plan gratuito (hasta 500 MB) alcanza, y permite que cualquiera lea los datos desde internet mientras que solo el robot, con una llave secreta, puede escribir. Así nadie puede alterar la información.

🌐 GitHub Pages + OpenStreetMap, la vidriera

GitHub es el sitio donde vive el código del proyecto, y además publica gratis la página web, que es un único archivo. Cuando alguien la abre, pide los datos directamente a Supabase y los dibuja. El mapa de fondo viene de OpenStreetMap, un mapa mundial libre y colaborativo.

04¿Qué pasa cada 2 minutos?

sequenceDiagram
    autonumber
    participant R as 🤖 Robot (Supabase)
    participant E as 🚇 EMOVA
    participant S as 🗄️ Base de datos
    Note over R: Suena el despertador (cada 2 min)
    R->>E: ¿Cómo están todos los equipos?
    E-->>R: Lista completa (~424 equipos)
    R->>S: ¿Cómo estaban la última vez?
    S-->>R: Estado anterior de cada equipo
    Note over R: Compara uno por uno
    R->>S: Actualizá el estado actual de todos
    alt Hubo cambios
        R->>S: Anotá en el historial solo los que cambiaron
    else No cambió nada
        Note over R,S: No se agrega nada al historial
    end
    Note over R: Se apaga hasta la próxima

Todo el ciclo tarda unos pocos segundos.

05La idea clave: anotar solo los cambios

Guardar una “foto” completa de los 424 equipos cada 2 minutos serían más de 300.000 anotaciones por día, casi todas repetidas (“sigue funcionando”, “sigue funcionando”…). El espacio gratuito se llenaría en pocos días.

En cambio, el proyecto hace lo que haría una persona prolija con una libreta: solo escribe cuando algo cambia.

flowchart TD
    Q["El robot consulta un equipo
(ej: ascensor de Estación Callao)"]
    P{"¿Está igual que
la vez anterior?"}
    N["No se anota nada nuevo
(solo la hora de la consulta)"]
    Y["Se anota en el historial:
'14:35 — pasó de funcionando
a fuera de servicio'"]
    Q --> P
    P -- "Sí, igual" --> N
    P -- "No, cambió" --> Y

Con este método, según las mediciones hechas, el espacio gratuito alcanza para aproximadamente 20 meses de historial. Cuando se acerque al límite, los datos viejos se pueden archivar aparte.

06Cómo está organizada la información

La base de datos tiene tres “planillas”:

Tamaño fijo
📋 Catálogo de equipos
Un renglón por ascensor o escalera, con su línea, estación y descripción. Se escribe una sola vez (~424 renglones).
Tamaño fijo
🟢 Estado actual
Cómo está cada equipo ahora mismo y desde cuándo. Se pisa en cada consulta, así que siempre ocupa lo mismo.
Crece
📜 Historial de cambios
Un renglón por cada vez que un equipo cambió de estado. Permite responder “¿cuántas veces falló este ascensor este mes?”.

Para no repetir “Línea B – Callao – Ascensor de andén a vestíbulo” miles de veces, el historial solo guarda un número que apunta al catálogo, como un número de ficha. Eso ahorra mucho espacio.

07La página web: qué ve la gente

Cuando alguien abre la página, primero le pide a la base una consulta fresca a EMOVA (si tarda, sigue sin esperar) y después trae los datos. La página no necesita un servidor propio: lee directo de Supabase, que solo permite leer.

PestañaQué muestra
Estado actualPrimero, los equipos fuera de servicio en este momento. Debajo, todas las líneas para desplegar y ver cada equipo.
HistóricoSe elige un rango de tiempo y aparece un gráfico con la cantidad de cambios y el detalle de qué pasó con cada equipo.
MapaEl trazado de las líneas sobre el mapa de la ciudad, con cada estación pintada según qué parte de sus equipos funciona: todo ok · parcial · todo caído

09Preguntas frecuentes

¿Los datos son oficiales?

Vienen de la información pública de EMOVA. El proyecto no los modifica: solo los guarda y los ordena. Si EMOVA informa algo incorrecto, acá se va a ver igual.

¿Qué tan actualizados están?

Se consultan cada 2 minutos y, además, cada vez que alguien abre la página se intenta hacer una consulta en el momento.

¿Puede alguien alterar los datos?

No. Leer es público, pero escribir requiere una llave secreta que solo tiene el robot recolector.

¿Qué pasa si EMOVA se cae un rato?

Esa consulta falla y no se anota nada; en la siguiente, 2 minutos después, se retoma normalmente. La página sigue mostrando el último estado conocido.

¿Cuánto cuesta mantenerlo?

Nada: Supabase y GitHub se usan dentro de sus planes gratuitos. Se estima que el espacio gratuito alcanza para cerca de 20 meses de historial.

¿Se guarda algo de quienes visitan la página?

No. El proyecto solo guarda el estado de los equipos del subte.

¿Se pueden usar los datos para otra cosa?

Sí. Como la lectura es pública, cualquier persona u organización puede consultarlos para hacer sus propios análisis o informes.

10Glosario

API
Una “ventanilla” en internet donde un programa le pide datos a otro.
Equipo / acceso
Cada ascensor o escalera mecánica del subte.
Base de datos
Un lugar ordenado donde se guarda información para consultarla después.
Nube
Computadoras de otras empresas que se usan a través de internet.
Despertador (cron)
Una tarea programada para ejecutarse sola en un horario fijo.
Historial
El registro de cada cambio de estado, con su fecha y hora.
Plan gratuito
El nivel de uso que un servicio ofrece sin cobrar.
GitHub
Sitio donde se guarda y comparte el código de programas.
Supabase
Servicio de base de datos en la nube.
OpenStreetMap
Mapa del mundo libre, hecho por una comunidad de voluntarios.
